# כתיבת חתימות IDPS מורכבות באמצעות Regex — מדריך לתלמידים

> מדריך זה מבוסס על המצגת ומרחיב כל דוגמה עם הסבר פשוט למתחילים.

---

## רקע קצר — מה זה IDPS ולמה Regex?

### מה זה IDPS?

**IDPS** = Intrusion Detection and Prevention System  
מערכת שמזהה ו/או חוסמת תעבורת רשת חשודה.

כדי לזהות תעבורה חשודה, ה-IDPS משתמש ב**חתימות (Signatures)** — כמו "כתובות אצבע" לדפוסים מסוכנים.

### מה זה Regex (ביטויים רגולריים)?

**Regex** (Regular Expressions) = שפה לחיפוש דפוסים בטקסט.

| ביטוי Regex | משמעות | דוגמה לתאימות |
|------------|--------|--------------|
| `[a-z]` | אות קטנה כלשהי | `a`, `g`, `z` |
| `[0-9]` | ספרה כלשהי | `0`, `5`, `9` |
| `[2-8]` | ספרה בין 2 ל-8 | `3`, `7` |
| `{3}` | בדיוק 3 פעמים | `aaa` |
| `{2,}` | 2 פעמים לפחות | `aa`, `aaa`, `aaaa` |
| `.` | כל תו כלשהו | `a`, `5`, `@` |
| `\.` | נקודה ממש (לא כל תו) | `.` |
| `^` | התחלת מחרוזת | `^abc` → מתחיל ב-abc |
| `$` | סוף מחרוזת | `abc$` → מסתיים ב-abc |
| `\|` | או (OR) | `cat\|dog` → cat **או** dog |

## איך בנויה חתימת IDPS מתקדמת?

חתימה מתקדמת מורכבת מ**כמה חוקים** המחוברים בלוגיקה:

```
חוק1 && חוק2 && חוק3   ← כולם יחד (AND)
חוק1 || חוק2            ← אחד מהם (OR)
```

### כל חוק מכיל 4 פרמטרים:

| פרמטר | תפקיד | דוגמה |
|-------|--------|--------|
| **Location** | **איפה** לחפש בפקטה | `TCP Header`, `IPv4 Header`, `HTTP Payload` |
| **Offset** | **היסט** — מאיזה byte להתחיל לספור | `0`, `12`, `13` |
| **Scope** | **טווח** — כמה bytes לבדוק | `1`, `2`, `4`, `all` |
| **Pattern** | **מה** לחפש — בינארי או Regex | `00000010`, `[a-z]irus[2-8]` |

## מבנה מנות TCP ו-IPv4 — טבלאות עזר

### TCP Header — מבנה:

```
Bytes 0-1:   Source Port      (פורט מקור)
Bytes 2-3:   Destination Port (פורט יעד)
Bytes 4-7:   Sequence Number
Bytes 8-11:  Acknowledgment Number
Byte 12:     Data Offset + Reserved
Byte 13:     FLAGS (דגלים)
Bytes 14-15: Window Size
```

### דגלי TCP — Byte 13:

```
Bit: 7   6   5   4   3   2   1   0
     URG ACK PSH RST SYN FIN  -   -
```

| דגל | Bit | ערך (decimal) | ערך (בינארי) |
|-----|-----|--------------|------------|
| FIN | 0 | 1 | 00000001 |
| SYN | 1 | 2 | 00000010 |
| RST | 2 | 4 | 00000100 |
| PSH | 3 | 8 | 00001000 |
| ACK | 4 | 16 | 00010000 |
| URG | 5 | 32 | 00100000 |

### IPv4 Header — מבנה:

```
Bytes 0-3:   Version, IHL, TOS, Total Length
Bytes 4-7:   Identification, Flags, Fragment Offset
Bytes 8-11:  TTL, Protocol, Header Checksum
Bytes 12-15: Source IP Address       ← Offset 12
Bytes 16-19: Destination IP Address  ← Offset 16
```

## דוגמה 1 — תפיסת TCP עם Destination Port 52,000

### המטרה

> לתפוס כל פקטת TCP שמגיעה ל**פורט יעד 52,000**

### חישוב — המרת 52,000 לבינארי

```
52,000 בעשרוני → הגדלה לשני bytes
52,000 = 203 × 256 + 32

Byte גבוה: 203 = 11001011
Byte נמוך:  32 = 00100000

Pattern:  1100101100100000
```

**בדיקה מהירה:**
```
1100 1011  = 0xCB = 203
0010 0000  = 0x20 = 32
203 × 256 + 32 = 51968 + 32 = 52,000 ✓
```

### החתימה המלאה

| פרמטר | ערך | הסבר |
|-------|-----|------|
| **Location** | `TCP Header` | מסתכלים בכותרת TCP |
| **Offset** | `2` | Bytes 0–1 הם פורט מקור — פורט יעד מתחיל ב-Byte 2 |
| **Scope** | `2` | פורט תופס 2 bytes |
| **Pattern** | `1100101100100000` | ייצוג בינארי של 52,000 |

### הסבר לתלמיד מתחיל

> תחשוב על כותרת ה-TCP כמו מעטפה. ה-Offset הוא "מיקום השדה במעטפה".  
> פורט המקור נמצא במיקומים 0–1. פורט היעד נמצא מיד אחריו — מיקומים 2–3.  
> לכן Offset=2, Scope=2 = "תסתכל על 2 bytes החל ממיקום 2".  
> כמו לספור אצבעות: 0, 1, **2, 3** ← כאן פורט היעד.

## דוגמה 2 — תפיסת TCP עם דגלי SYN ו-PUSH פעילים

### המטרה

> לתפוס כל פקטת TCP שבה **שני הדגלים SYN ו-PSH מופעלים יחד**

### חישוב — ערך byte הדגלים

```
SYN  = bit 1 = ערך  2 = 0000 0010
PSH  = bit 3 = ערך  8 = 0000 1000

SYN + PSH = 2 + 8 = 10 → 0000 1010
```

**ויזואלי:**

```
Bit: 7  6  5  4  3  2  1  0
     0  0  0  0  1  0  1  0
              ↑     ↑
             PSH   SYN
```

### החתימה המלאה

| פרמטר | ערך | הסבר |
|-------|-----|------|
| **Location** | `TCP Header` | מסתכלים בכותרת TCP |
| **Offset** | `13` | Byte 13 הוא שדה הדגלים ב-TCP |
| **Scope** | `1` | שדה הדגלים הוא byte אחד בלבד |
| **Pattern** | `00001010` | SYN (bit 1) + PSH (bit 3) = ערך 10 |

### הסבר לתלמיד מתחיל

> TCP Flags הם כמו מתגי הדלקה/כיבוי. כל bit הוא מתג אחד.  
> SYN = "אני רוצה להתחיל חיבור".  
> PSH = "שלח את הנתונים מיד, אל תחכה".  
> כשמחפשים שני דגלים ביחד, **מחברים** את ערכיהם (2 + 8 = 10 = 00001010).  
> Offset 13 = עמוד 13 בספר ה-TCP — שם תמיד נמצאים הדגלים.

## דוגמה 3 — תפיסת פקטות מטווח כתובות IP

### המטרה

> לתפוס כל פקטת IP שמגיעה **מטווח הכתובות 1.1.1.1 עד 1.1.1.25**

### חישוב — Regex לטווח IP

```
כתובת IP: [בייט1].[בייט2].[בייט3].[בייט4]

הטווח שלנו: 1.1.1.X   כאשר X בין 1 ל-25

חלק קבוע:  1\.1\.1\.
חלק משתנה: 1 עד 25 ← צריך Regex!
```

**Regex לטווח 1–25:**

```
([1-9]|1[0-9]|2[0-5])
```

| חלק | מה הוא מכסה | דוגמאות |
|-----|------------|---------|
| `[1-9]` | ספרה בודדת 1–9 | 1, 5, 9 |
| `1[0-9]` | מספרים 10–19 | 10, 14, 19 |
| `2[0-5]` | מספרים 20–25 | 20, 23, 25 |

**Pattern המלא:**

```regex
^1\.1\.1\.([1-9]|1[0-9]|2[0-5])$
```

### החתימה המלאה

| פרמטר | ערך | הסבר |
|-------|-----|------|
| **Location** | `IPv4 Header` | מסתכלים בכותרת IPv4 |
| **Offset** | `12` | Bytes 12–15 הם כתובת ה-Source IP |
| **Scope** | `4` | כתובת IP תופסת 4 bytes (4 אוקטטים) |
| **Pattern** | `^1\.1\.1\.([1-9]\|1[0-9]\|2[0-5])$` | Regex לטווח 1.1.1.1–1.1.1.25 |

### הסבר לתלמיד מתחיל

> כתובת IP כמו `1.1.1.17` מיוצגת ב-4 bytes ברצף.  
> Offset 12 = "קפוץ 12 bytes קדימה בכותרת IP, שם נמצאת כתובת המקור".  
> Scope 4 = "בדוק 4 bytes רצופים — כל כתובת IP שלמה".  
> הטריק ב-Regex: אי אפשר לכתוב `1-25` ישירות — צריך לחלק לקבוצות (1-9, 10-19, 20-25).  
> `\.` = נקודה ממש (ב-Regex, נקודה רגילה מייצגת **כל** תו, לכן מוסיפים `\`).

## דוגמה 4 — תפיסת HTTP Response עם מחרוזת XirusY

### המטרה

> לתפוס כל פקטת HTTP Response שמכילה בתוכן שלה את המחרוזת **XirusY**  
> כאשר: X = אות קטנה באנגלית, Y = ספרה בין 2 ל-8

**דוגמאות לתאימות:** `virus3`, `avirus8`, `xirus2`  
**ללא תאימות:** `Virus3` (V גדולה), `virus9` (9 מחוץ לטווח), `VIRUS5` (אותיות גדולות)

### Pattern — Regex

```regex
[a-z]irus[2-8]
```

| חלק | משמעות |
|-----|--------|
| `[a-z]` | X = **כל** אות קטנה (a עד z) |
| `irus` | המחרוזת הקבועה |
| `[2-8]` | Y = ספרה בין 2 ל-8 |

### החתימה הבסיסית

| פרמטר | ערך | הסבר |
|-------|-----|------|
| **Location** | `HTTP Payload` | מחפשים בתוכן (body) של ה-HTTP |
| **Offset** | `0` | מתחילים מתחילת ה-Payload |
| **Scope** | `all` | בודקים את כל ה-Payload |
| **Pattern** | `[a-z]irus[2-8]` | Regex לזיהוי XirusY |

### הבעיה עם החתימה הבסיסית

> **החוק הזה בעייתי!** הוא יבדוק:
> - תעבורה **יוצאת** גם — לא רק נכנסת
> - **כל** שרתי החברה — לא רק שרת ספציפי

### החתימה המשופרת — שני חוקים עם &&

**נוסיף חוק נוסף שמזהה את שרת היעד לפי IP:**

```
חוק1 (Payload) && חוק2 (IP יעד)
```

**חוק 1 — זיהוי ה-Pattern:**

| פרמטר | ערך |
|-------|-----|
| Location | `HTTP Payload` |
| Offset | `0` |
| Scope | `all` |
| Pattern | `[a-z]irus[2-8]` |

**חוק 2 — זיהוי IP שרת היעד (לדוגמה `192.168.1.1`):**

| פרמטר | ערך | הסבר |
|-------|-----|------|
| Location | `IPv4 Header` | כותרת IP |
| Offset | `16` | Bytes 16–19 = Destination IP |
| Scope | `4` | 4 bytes לכתובת IP |
| Pattern | ייצוג בינארי של ה-IP | כל IP לפי הצורך |

### הסבר לתלמיד מתחיל

> **למה לא מספיק חוק אחד?**  
> תחשוב על שומר בכניסה לבניין. אם הוא בודק רק שהמבקר נושא שם "virus" — הוא יעצור גם עובדים שמדברים על וירוס קר.  
> חוק טוב **חד** יותר: רק שם **וגם** מגיע לדלת הנכונה.  
>  
> הוספת חוק ה-IP מצמצמת את החוק לפקטות שמיועדות **רק** לשרת ספציפי — הרבה פחות False Positives.

### שאלה 1 — TCP מפורט (מספר פורט ספציפי)

> כתבו חתימה מדויקת שתתפוס כל פקטת TCP המגיעה **מפורט מסוים**.

**פתרון לדוגמה — פורט מקור 4444:**

**חישוב:**
```
4444 = 17 × 256 + 92
Byte גבוה: 17  = 00010001
Byte נמוך:  92 = 01011100
Pattern: 0001000101011100
```

| פרמטר | ערך | הסבר |
|-------|-----|------|
| **Location** | `TCP Header` | כותרת TCP |
| **Offset** | `0` | Bytes 0–1 = Source Port (פורט **מקור**) |
| **Scope** | `2` | פורט = 2 bytes |
| **Pattern** | `0001000101011100` | בינארי של 4444 |

> **הסבר:** פורט המקור נמצא ב-Bytes 0–1, לכן Offset=0.  
> המרת הפורט לבינארי: חלוקה ל-2 bytes → הרכבה.

### שאלה 2 — טווח IP: 192.168.127.5-155

> כתבו חתימה מדויקת שתתפוס כל פקטה שמגיעה **מטווח ה-IP: 192.168.127.5 עד 192.168.127.155**

**חישוב Regex לטווח 5–155:**

```
5   עד  9   →  [5-9]
10  עד  99  →  [1-9][0-9]
100 עד 149  →  1[0-4][0-9]
150 עד 155  →  15[0-5]
```

**Pattern המלא:**

```regex
^192\.168\.127\.([5-9]|[1-9][0-9]|1[0-4][0-9]|15[0-5])$
```

| פרמטר | ערך |
|-------|-----|
| **Location** | `IPv4 Header` |
| **Offset** | `12` |
| **Scope** | `4` |
| **Pattern** | `^192\.168\.127\.([5-9]\|[1-9][0-9]\|1[0-4][0-9]\|15[0-5])$` |

> **הסבר:** הטווח 5–155 מחייב חלוקה ל-4 קבוצות כי Regex לא מבין "5 עד 155" ישירות.  
> בודקים כל "משפחה" בנפרד: ספרה בודדת (5–9), שתי ספרות (10–99), שלוש ספרות (100–155).

**שני חוקים עם &&:**

**חוק 1 — פורט מקור 80:**
```
80 = 0 × 256 + 80
Byte גבוה: 0  = 00000000
Byte נמוך: 80 = 01010000
Pattern: 0000000001010000
```

| פרמטר | ערך |
|-------|-----|
| Location | `TCP Header` |
| Offset | `0` |
| Scope | `2` |
| Pattern | `0000000001010000` |

**חוק 2 — דגל SYN:**

| פרמטר | ערך |
|-------|-----|
| Location | `TCP Header` |
| Offset | `13` |
| Scope | `1` |
| Pattern | `00000010` |

**החתימה:** חוק1 `&&` חוק2

> החתימה תזהה ניסיונות חיבור מצד שרתי HTTP — שימושי לזיהוי Port Scanning.

### שאלה 4 — UDP מ-215.154.63.4 על פורט 80

> כתבו חתימה שתתפוס כל פקטת UDP **הנשלחת מ-215.154.63.4 מפורט 80**

**שני חוקים עם &&:**

**חוק 1 — כתובת IP מקור:**
```
215 = 11010111
154 = 10011010
 63 = 00111111
  4 = 00000100
Pattern: 11010111100110100011111100000100
```

| פרמטר | ערך |
|-------|-----|
| Location | `IPv4 Header` |
| Offset | `12` |
| Scope | `4` |
| Pattern | `11010111100110100011111100000100` |

**חוק 2 — פורט UDP מקור 80:**

```
UDP Header: Bytes 0-1 = Source Port
80 = 0000000001010000
```

| פרמטר | ערך |
|-------|-----|
| Location | `UDP Header` |
| Offset | `0` |
| Scope | `2` |
| Pattern | `0000000001010000` |

**החתימה:** חוק1 `&&` חוק2

> **הסבר:** UDP שונה מ-TCP — אין Handshake. מבנה ה-Header של UDP:  
> Bytes 0–1: Source Port | Bytes 2–3: Destination Port | Bytes 4–5: Length | Bytes 6–7: Checksum  
> לכן פורט המקור נמצא ב-Offset 0, בדיוק כמו ב-TCP.

### שאלה 5 — HTTP לשרת 192.145.21.3 עם Payload מורכב

> תתפסו כל פקטת HTTP ל**פורט 37458** ל**שרת 192.145.21.3** שמכילה בPayload את:  
> **Virus.X.Y** כאשר:  
> X = אות קטנה באנגלית (2 ויותר תווים)  
> Y = ספרה בין 2–5, **בדיוק 8 ספרות**

**שלושה חוקים עם &&:**

**חוק 1 — IP יעד 192.145.21.3:**
```
192 = 11000000
145 = 10010001
 21 = 00010101
  3 = 00000011
Pattern: 11000000100100010001010100000011
```

| פרמטר | ערך |
|-------|-----|
| Location | `IPv4 Header` |
| Offset | `16` |
| Scope | `4` |
| Pattern | `11000000100100010001010100000011` |

**חוק 2 — פורט יעד 37458:**
```
37458 = 146 × 256 + 82
Byte גבוה: 146 = 10010010
Byte נמוך:  82 = 01010010
Pattern: 1001001001010010
```

| פרמטר | ערך |
|-------|-----|
| Location | `TCP Header` |
| Offset | `2` |
| Scope | `2` |
| Pattern | `1001001001010010` |

**חוק 3 — Payload: Virus.X.Y:**

```regex
Virus\.[a-z]{2,}\.[2-5]{8}
```

| חלק Regex | משמעות |
|-----------|--------|
| `Virus\.` | המחרוזת "Virus" + נקודה ממש |
| `[a-z]{2,}` | X = 2 אותיות קטנות ויותר |
| `\.` | נקודה ממש |
| `[2-5]{8}` | Y = בדיוק 8 ספרות מהטווח 2–5 |

| פרמטר | ערך |
|-------|-----|
| Location | `HTTP Payload` |
| Offset | `0` |
| Scope | `all` |
| Pattern | `Virus\.[a-z]{2,}\.[2-5]{8}` |

**החתימה המלאה:** חוק1 `&&` חוק2 `&&` חוק3

> **הסבר:** שלושה חוקים = שלושה מסננים. רק פקטה שעוברת **את שלושתם** תתפס:  
> 1. מגיעה ל-IP הנכון  
> 2. מגיעה לפורט הנכון  
> 3. מכילה את המחרוזת המדויקת ב-Payload  
>  
> **דוגמה לתאימות:** `Virus.abc.22345253` ← ab=2 אותיות ✓, 22345253=8 ספרות בטווח 2–5 ✓  
> **ללא תאימות:** `Virus.a.22345253` ← רק אות אחת ✗

## טבלת עזר מהירה — חישוב פורטים נפוצים לבינארי

| פורט | Decimal | Hex | Byte גבוה | Byte נמוך | בינארי (16 bit) |
|------|---------|-----|-----------|-----------|----------------|
| **80** | 80 | 0x0050 | 00000000 | 01010000 | `0000000001010000` |
| **443** | 443 | 0x01BB | 00000001 | 10111011 | `0000000110111011` |
| **22** | 22 | 0x0016 | 00000000 | 00010110 | `0000000000010110` |
| **3389** | 3389 | 0x0D3D | 00001101 | 00111101 | `0000110100111101` |
| **8080** | 8080 | 0x1F90 | 00011111 | 10010000 | `0001111110010000` |

> **כיצד לחשב בעצמך:**  
> פורט ÷ 256 = Byte גבוה (השאר = Byte נמוך)  
> המר כל byte לבינארי (8 bits) → שרשר יחד

| **Location נכון** | TCP header לפורטים/דגלים, IPv4 header ל-IP, HTTP payload לתוכן |
| **Offset מדויק** | Source port = 0, Dest port = 2, Flags = 13, Source IP = 12, Dest IP = 16 |
| **Scope = גודל השדה** | פורט = 2, IP = 4, דגלים = 1 |
| **חוקים + &&** | כמה תנאים ביחד = חתימה מדויקת יותר = פחות False Positives |
| **Regex לטווחים** | חלק לקבוצות: ספרה בודדת, שתי ספרות, שלוש ספרות |
| **בינארי לפורטים** | חלק ל-2 bytes → המר כל אחד ל-8 bits → שרשר |
