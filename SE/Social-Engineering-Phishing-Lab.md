# מעבדת הנדסה חברתית (Phishing) — מדריך לתלמידים

> תיקייה: `SE/`  
> הדגמת דיוג (Phishing) בכיתה — **עם הסכמה מדעת בלבד**.

---

## מטרות למידה

בסיום השיעור התלמיד/ה יוכל/י:

- להסביר מהי **הנדסה חברתית** ומהו **Phishing**
- לזהות רמזים לדף התחברות מזויף
- להבין איך נאספים פרטי התחברות בדף מדומה
- לתאר כללי אתיקה והסכמה בתרגיל כיתתי
- להציע הגנות למשתמשים ולארגון

---

## מה זה הנדסה חברתית?

**Social Engineering** = תקיפה דרך **אנשים**, לא דרך באג בקוד.

| סוג | דוגמה |
|-----|--------|
| **Phishing** | מייל/SMS עם קישור לדף מזויף |
| **Vishing** | שיחת טלפון מתחזת |
| **Pretexting** | סיפור כיסוי ("אני מתמיכה טכנית…") |
| **Baiting** | USB "אבוד" / הצעה מפתה |

> **בקצרה:** התוקף משכנע אותך למסור מידע או לבצע פעולה — בלי לפרוץ את השרת.

---

## מה מדגימה המעבדה הזו?

אפליקציית web קטנה עם שני מסכים:

| מסך | כתובת | למי |
|-----|--------|-----|
| דף התחברות מדומה | `/login.html` | "הקורבן" (מתנדב בכיתה) |
| לוח מרצה | `/dashboard.html` | המרצה — רואה פרטים בזמן אמת |

המותג פיקטיבי: **SecureMail**.

```
מתנדב מקליד שם+סיסמה בדף המזויף
              │
              ▼
        server.js (בזיכרון בלבד)
              │
              ▼  WebSocket
     Dashboard על המקרן  ← "וואו מומנט"
```

## מבנה התיקייה

```
SE/
├── README.md
├── server.js              ← Express + Socket.io
├── package.json
├── Dockerfile
├── docker-compose.yml
├── user-data.sh           ← פריסה אופציונלית ב-AWS (זהירות!)
└── public/
    ├── login.html/.css/.js      ← דף הדיוג המדומה
    └── dashboard.html/.css/.js  ← לוח המרצה
```

| קובץ | תפקיד |
|------|--------|
| `server.js` | מקבל POST של פרטים, שומר **רק בזיכרון**, משדר ל-dashboard |
| `login.*` | נראה כמו דף התחברות + באנר "סביבת הדגמה" |
| `dashboard.*` | מציג captures בזמן אמת + כפתור מחיקה |

---

## כללי אתיקה — חובה לפני ההרצה

1. **הסכמה מדעת** — להסביר למשתתפים שזו הדגמה
2. **סיסמאות פיקטיביות בלבד** — לא Gmail / בנק / עבודה
3. **רשת כיתה / מקומית** — לא לחשוף לאינטרנט הפתוח בלי בקרה
4. **Debrief בסוף** — מה היו הרמזים שזה מזויף?
5. **מחיקת נתונים** — כפתור ב-dashboard בסיום

> יש באנר אדום בדף ההתחברות: **"סביבת הדגמה לקורס"** — אל תסירו אותו בהדגמה.

## הרצה מהירה (Docker)

```bash
cd SE
docker compose up -d --build
```

| מה | כתובת |
|----|--------|
| דף למתנדבים | `http://localhost:3000/login.html` |
| לוח מרצה | `http://localhost:3000/dashboard.html` |

ממחשבים אחרים **באותה רשת**:

```text
http://<IP-של-המחשב-המארח>:3000/login.html
```

(ב-Windows: `ipconfig` → IPv4)

**עצירה:**

```bash
docker compose down
```

### ללא Docker

```bash
npm install
npm start
```

## מה קורה מאחורי הקלעים?

| שלב | מה קורה |
|-----|---------|
| 1 | המתנדב שולח טופס (username + password) |
| 2 | `POST /api/capture` שומר בזיכרון (`captures[]`) |
| 3 | `socket.io` שולח `new-capture` לכל ה-dashboards |
| 4 | על המסך מופיעים הפרטים מיד |
| 5 | למתנדב מוצג הסבר (debrief) שזו הייתה הדגמה |

**חשוב:** הנתונים **לא** נשמרים לקובץ / DB — נמחקים כשעוצרים את השרת.

## מבנה שיעור מומלץ (20–30 דק')

| דקה | פעילות |
|-----|--------|
| 0–3 | לוח מרצה ריק על המקרן |
| 3–8 | שליחת קישור למתנדב (אפשר כ"הודעה מדומה") |
| 8–12 | הקלדה → הופעה חיה על המסך |
| 12–22 | דיון: רמזים לדף מזויף |
| 22–25 | מחיקת נתונים + סיכום הגנות |

---

## רמזים לדף מזויף — מה לחפש?

| רמז | למה זה חשוד |
|-----|-------------|
| **URL** | לא הדומיין הרשמי (`securemail-login.xyz` במקום `mail.company.com`) |
| **HTTP במקום HTTPS** | אין מנעול / תעודה |
| **לחץ ודחיפות** | "החשבון ייחסם תוך שעה" |
| **שגיאות עיצוב / תרגום** | לוגו מטושטש, ניסוח מוזר |
| **בקשה לסיסמה במייל/SMS** | שירותים לגיטימיים לא מבקשים כך |
| **קישור מקוצר / מוזר** | מסתיר את היעד האמיתי |

## הגנות — למשתמש ולארגון

### למשתמש

- לבדוק את כתובת האתר לפני הקלדת סיסמה
- לא ללחוץ על קישורים בהודעות לחץ
- MFA (אימות דו-שלבי) — גם אם הסיסמה דלפה, קשה יותר
- Password manager — לא ממלא אוטומטית באתר זר

### לארגון

- הדרכות Phishing + תרגילי דיוג מבוקרים
- SPF / DKIM / DMARC למייל
- דיווח על מיילים חשודים
- סיסמאות חזקות + MFA חובה
- ניטור כניסות חריגות

## שאלות לדיון / בדיקה עצמית

1. למה Phishing נחשב להנדסה חברתית ולא לפריצת שרת?
2. מה ההבדל בין הדגמה כיתתית לבין תקיפה אמיתית מבחינת אתיקה?
3. ציינו 4 רמזים לדף מזויף.
4. למה MFA מקטין נזק גם אחרי דיוג מוצלח?
5. איפה נשמרים הנתונים במעבדה הזו?

<details>
<summary>תשובות</summary>

1. התוקף משכנע אדם למסור מידע — בלי לנצל באג בקוד השרת של הקורבן  
2. בהדגמה: הסכמה, סיסמאות פיקטיביות, שקיפות, מחיקה. בתקיפה: הטעיה ללא הסכמה — לא חוקי  
3. URL, חוסר HTTPS, לחץ, עיצוב/לשון חשודה  
4. בלי הקוד השני אי אפשר להתחבר (ברוב המקרים)  
5. בזיכרון השרת בלבד — לא בדיסק

## אזהרות פריסה (AWS / אינטרנט)

בתיקייה יש גם קבצי פריסה (`user-data.sh` וכו').  
אם בכל זאת מריצים מרוחק:

- חובה סיסמת גישה (Basic Auth ב-`server.js`)
- **לא** להשאיר פתוח לאינטרנט בלי בקרה
- לא לשמור סיסמאות אמיתיות בקבצי טקסט ב-repo

> אל תעלו ל-GitHub קבצים כמו `aws-demo-password.txt` / `public-ip.txt` עם סודות.
